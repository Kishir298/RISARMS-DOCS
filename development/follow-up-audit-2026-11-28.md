# Follow-up audit and fix list — 2026-11-28

Items are ordered by risk. Each is a known limitation of the completed work,
not a hidden defect: none of them is claimed as done anywhere else.

| # | Area | Limitation | Fix | Risk if ignored |
| --- | --- | --- | --- | --- |
| 1 | TIVISS-HOST | Legacy AI modules (`tiviss/personality`, conversation, voice, model providers, handover) still exist on disk and are only *unwired*. `pyproject` may still expose their entry points. | Inventory every legacy module and console script; delete code and entry points; keep a `CHANGELOG` note; verify no import path or UI reference remains. | A user or script could still run the retired agent; docs and code disagree. |
| 2 | RESCS wiring | `QuotaManager` is a library. `FileService` still enforces its own `max_*_per_owner` settings; uploads, retries and memory sync do not consult one shared policy object. | Inject one `QuotaManager` into files/uploads/memory; map legacy settings to it; keep the lock covering the whole write path; add a concurrent upload+sync test. | Two independent quota paths can disagree; over-quota growth may be admitted. |
| 3 | RESCS transport | `report_to_core()` builds the payload but no HTTP route sends it; CORE does not ingest quota/capacity reports yet. | Add an authenticated RESCS→CORE report endpoint and a scheduler push; drive RISARMS-ui quota display from it. | Admins see no storage headroom; quota UI remains absent. |
| 4 | ASIS sync | RESCS quota is not consulted before a memory sync write; there is no per-memory local-only/synced toggle in the UI. | Add quota pre-check to `MemorySyncService.push`, map 507/quota responses to a retryable status, add the toggle. | Sync can exceed the AI-memory cap; users cannot choose what leaves the device. |
| 5 | TIVISS-CLIENT | Offline event delivery has no jittered backoff schedule beyond immediate retry on the next run, and no health-report queue (only security events). | Add exponential backoff with jitter and a persistence-backed attempt clock; generalise the queue for health reports. | Retry storms when a server returns; supervision loses client history during outages. |
| 6 | CORE / clients | CORE-CLIENT does not render the new pending-device state; an unapproved device sees a generic login failure. | Surface `pending`/`rejected` distinctly in CORE-CLIENT and RISARMS-ui login; add a "waiting for approval" screen. | Users cannot tell a typo from a pending approval. |
| 7 | ASCS | `ALLOW_FOR_ME` read-only classification is an executable/argv allowlist; there is no OS sandbox, and `FULL_ACCESS` still permits writes inside the workspace only by convention. | Document workspace≠sandbox (done) and optionally add an OS-level confinement backend. | Users may over-trust the mode. |
| 8 | Supervision | Restart policy is advisory; no component executes restarts, and admission reserve values are unset for the HP 14 target. | Measure HP 14 RAM/storage on the real machine, set `reserve_bytes`, and decide whether any restart executor is needed beyond systemd/runit. | Admission may over- or under-commit on the target hardware. |
| 9 | Validation | Container, booted Ubuntu/Void, backup/restore/upgrade and physical HP 14 validation were **not** run. | Add CI container jobs for the install assertions and a documented manual boot checklist. | Deployment regressions reach users undetected. |
| 10 | Release | `components.lock.json` pins still reference pre-change commits; no release was published. | After this push, wait for CI, then update pins to the pushed commits and re-run staging/install checks. | A release built now would omit these changes. |
| 11 | CORE-CLIENT | Diverged from its remote (30 ahead, 2 behind); untouched. | Rebase onto `origin/main` after reviewing the two upstream commits, then push. | History drift and stale client behaviour. |
| 12 | Docs | `DOCS/README.md` history section still describes 2026-11-22 release runs as current; the requirement checklist is the accurate status source. | Trim or date-stamp the history section. | Readers may mistake old validation for current. |
