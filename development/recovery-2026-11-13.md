## 4. Defects repaired in code

### 4.1 Automatic reconnection never happened (confirmed)

`risarms_ui/connection/manager.py` changed connection state on heartbeat failure
but **never invoked `reconnect()`**. Worse, a failed attempt left `_stop` set,
which killed the monitor thread, and recovery set `ONLINE` without restoring the
WSS channel. The manager now:

- owns recovery in the monitor thread, scheduling one guarded attempt;
- applies bounded exponential backoff with jitter (never above `max_backoff`);
- refuses concurrent attempts (`_reconnect_lock`);
- re-authenticates with the stored device credential and refreshes the profile;
- restores the single-use-ticket control channel before reporting `ONLINE`;
- publishes `connection.restored` / `session.refreshed` events;
- halts on 401/403 or `session.revoked` and requires a fresh sign-in;
- ignores close callbacks from streams it deliberately replaced.

Regression coverage: `tests/test_reconnection.py` (9 tests).

### 4.2 Automatic synchronization only covered records

`app._auto_sync()` skipped everything unless a pending record existed. It now
synchronizes records, durable cloud uploads and queued messages, and resumes on
`connection.restored`. File uploads moved into `remote.sync_files()` so the
Files page and the background loop share one implementation.

### 4.3 Namespace collision between the desktop app and CORE-CLIENT

`risarms_ui` imported `client.web` and `client.inference` at module import time,
but RISARMS-ui also ships its own `client/` package. Imports therefore resolved
differently depending on install shape and working directory. `remote.py` now
uses the local `validate_origin`, and `local.py` loads `ChatStream` lazily with
an actionable error. `risarms_ui` no longer depends on the `client` name at
import time.
